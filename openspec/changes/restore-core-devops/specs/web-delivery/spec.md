# Spec Delta

## Purpose

让公开内容在首屏 HTML 中可读且具有一致的索引元数据，同时将认证和高交互工作区留在客户端并严格隔离私有内容。通过明确的部署和恢复流程，保证功能不只是单次演示可用。

## ADDED Requirements

### Requirement: 选择性渲染与索引
首页与公开仓库概览 SHALL 提供 SSR；认证设置、编辑和运行日志工作区采用客户端渲染。公开索引默认关闭；开启后 canonical、robots 和 sitemap MUST 一致，私有内容和工作区不得进入 sitemap。

#### Scenario: 无脚本读取公开页面
- **WHEN** 爬虫请求允许索引的公开仓库概览
- **THEN** 首屏 HTML 包含仓库名称、描述和正确 canonical，无需执行脚本

#### Scenario: 私有深链接
- **WHEN** 未认证请求私有仓库或交互工作区深链接
- **THEN** 响应不泄露私有正文或凭据，不进入公共缓存，且禁止索引

### Requirement: 交互一致性和隔离
新增流程 SHALL 保留现有主题切换、键盘访问、加载/失败反馈及移动布局；不同用户、仓库和版本的数据缓存 MUST 隔离，退出时清除私有客户端缓存。

#### Scenario: 切换账号
- **WHEN** 访问私有仓库的用户退出并登录另一无权账号
- **THEN** 旧缓存不能继续显示私有仓库内容

### Requirement: 浏览器凭据隔离
网页 SHALL 依靠 HttpOnly Cookie 完成 JWT 认证和续期，前端不得将认证或刷新令牌写入 localStorage、sessionStorage、可读取 Cookie 或持久化 Query 缓存。授权确认和 Device Flow 验证页面 MUST 展示客户端身份与请求权限，并要求用户显式操作，不得仅访问链接就批准授权。

#### Scenario: 浏览器存储检查
- **WHEN** 用户登录、续期、退出并切换账号
- **THEN** 网页脚本与浏览器本地存储中均无认证或刷新令牌原文，退出后旧私有页面和缓存不再可见

#### Scenario: 设备授权确认
- **WHEN** 用户打开设备验证地址并输入或带入 user code
- **THEN** 页面展示待确认设备请求，不自动批准，拒绝和过期均提供可理解的反馈

### Requirement: 自愿生日设置
网页 SHALL 提供仅本人可读写的生日祝贺设置，默认关闭；只保存用户主动填写的月日、时区和开启状态，不收集出生年份。用户 MUST 能修改、关闭和删除设置；未填写完整有效资料不能开启，资料不得进入公开页面、默认第三方授权或日志。

#### Scenario: 主动开启
- **WHEN** 用户填写有效月日、选择时区并显式开启
- **THEN** 系统保存本人设置；无效日期或时区被拒绝，不自动获取或推断生日

#### Scenario: 删除和隔离
- **WHEN** 用户删除设置，或另一用户尝试读取或修改
- **THEN** 删除清除该生日资料并关闭祝贺，跨用户请求被拒绝且不泄露设置

### Requirement: 可恢复运行
部署 SHALL 提供开发与生产启动说明及 Nix 入口；发布前 MUST 验证重启、数据库和 Git/日志一致性备份恢复，并记录未验证平台。

#### Scenario: 从备份恢复
- **WHEN** 在隔离环境恢复一次停止写入时制作的完整备份
- **THEN** 用户可读取仓库及关联协作记录，运行状态可恢复且不会重复执行已完成集成

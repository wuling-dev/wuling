# Spec Delta

## Purpose

让开发者无需访问服务端文件系统即可使用标准 Git 客户端托管仓库，并在网页上浏览准确版本的代码和提交。传输和浏览必须遵循同一套公开性、成员权限与资源限制。

## ADDED Requirements

### Requirement: 标准 Git HTTP 传输
系统 SHALL 支持标准 Git 客户端通过 HTTPS clone、fetch 和 push；匿名只能读公开仓库，私有读取和全部写入 MUST 校验用户权限及 PAT 范围。

#### Scenario: 首次推送空仓库
- **WHEN** 开发者使用有效写入 PAT 向空仓库推送分支
- **THEN** 推送成功，页面展示正确默认分支和可用 clone 地址

#### Scenario: 未授权私有读取
- **WHEN** 无权限客户端请求私有仓库的引用或对象
- **THEN** 系统拒绝传输且不泄露私有引用或对象内容

### Requirement: 版本浏览和资源限制
系统 SHALL 提供分支、目录、文件、提交历史、单次提交 diff 与安全 Markdown README；所有版本参数和路径 MUST 验证，二进制、大文件和超限 diff 必须有明确受限提示。

#### Scenario: 浏览固定提交
- **WHEN** 用户打开一个提交的文件并且分支随后更新
- **THEN** 显示内容仍对应该提交，不静默切换为分支最新内容

### Requirement: 引用更新事件
系统 SHALL 仅为成功更新的引用生成可去重事件，携带仓库、引用、更新前后 SHA 和操作者。

#### Scenario: 推送被拒绝
- **WHEN** 推送因权限或分支保护被拒绝
- **THEN** 不产生表示成功更新的流水线触发事件

### Requirement: Git remote 提示
系统 SHALL 在支持并协商进度通道的 push/fetch 会话中，通过标准协议向客户端发送可显示为 `remote:` 的维护公告和彩蛋消息。消息 MUST 有长度和数量上限，过滤终端控制字符，不包含凭据或未授权私有信息；提示故障不得改变仓库引用或推拉结果。

#### Scenario: 真实客户端显示提示
- **WHEN** 标准 Git 客户端执行有进度通道的 push 或 fetch
- **THEN** 客户端输出维护公告或启用的彩蛋消息，传输和引用结果与未启用提示时一致

#### Scenario: 无进度通道
- **WHEN** 客户端未协商进度输出、选择静默模式，或 pull 的 fetch 阶段未发生可发送进度的交换
- **THEN** 系统保持协议兼容，不向引用广告或 pack 数据插入裸文本，不承诺该次客户端一定显示提示

#### Scenario: 未授权与异常消息
- **WHEN** 请求未获仓库权限，或消息内容包含控制字符、超长文本及异常模板
- **THEN** 未授权请求不获得个性化信息；异常消息被拒绝或安全降级，不阻断正常授权传输

### Requirement: Opt-in 生日祝贺
生日 remote 祝贺 SHALL 默认关闭，仅向主动填写生日月日、选择时区并开启功能的当前认证用户发送。系统 MUST 按用户所选时区的月日精确匹配，不从提交作者推断生日；未填写、未开启、关闭或删除后不得发送，不向其他用户或匿名请求透露生日资料。

#### Scenario: 默认不启用
- **WHEN** 用户没有主动填写生日或未开启生日祝贺
- **THEN** Git 操作不产生生日祝贺，维护公告不受影响

#### Scenario: 自愿开启与关闭
- **WHEN** 用户已填写并开启且本次日期匹配，或随后关闭或删除设置
- **THEN** 匹配时仅在该用户的已授权进度通道发送通用祝贺；关闭或删除后的请求不再发送

#### Scenario: 时区和闰日
- **WHEN** 按用户选择的时区计算当前日期，或用户填写 2 月 29 日
- **THEN** 仅在月日精确相同时祝贺，不在其他时区日期或非闰年的替代日期提前或补发

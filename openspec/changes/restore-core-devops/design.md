# Design

## Context

见 proposal.md。当前后端集中在 `crates/server/src/main.rs`，`Repo` 与通用 `Item`
通过进程互斥写 JSON，权限只有管理员令牌；Git 已通过系统命令执行。
前端显式路由树区分 SSR 概览和 `ssr: false` 工作区，主题位于 `frontend/themes`，
HeroUI 与 TanStack Query/Virtual 已在依赖中，但尚未形成分域交互数据层。
现有测试覆盖基础资源、Git 浏览/快进合并、适配器、生产 HTTP 与 SPA shell。

旧版 `internal/githttp` 有真实 Git 协议测试，`issuehttp` / `mrhttp` 有讨论评审流程；
`pipeline` / `runnerhttp` 与 `runners/runner-clients` 可参考，但旧控制面是 Go、
Runner 使用 HTTP，不满足新 gRPC 决策。旧代码存在不等于新平台已交付。

## Goals / Non-Goals

**Goals:**
- 分阶段替换原型，先交付本地身份与 HTTP Git，再叠加协作和真实 CI。
- 每批有拒绝权限、并发和故障场景测试；规格只在归档后成为主规格。
- 公共页面允许匿名 SSR；认证凭据不得置于服务端模块全局变量或公共缓存。

**Non-Goals:**
- 不恢复旧版全量组织/项目层级，不引入实时 CRDT 和 DeltaDB 副本协议。
- 不兼容旧 Go 数据库的自动升级；仅迁移当前 Rust 原型 JSON。
- 不实现全 Actions 生态、云资源调度或任意不可信代码的强隔离。

## Decisions

### 1. 事务元数据与仓库级归属

采用 PostgreSQL 和版本化迁移；将身份、仓库成员、Issue、MR、工作区版本、
运行/任务/尝试分别建模，Git 对象仍保留在磁盘裸仓库。
SQLite 更易单机部署，但任务并发摘取与恢复需求更适合 PostgreSQL；
继续扩大 JSON 模型无法可靠支持多身份、租约和事务事件。
首版用户拥有仓库，直接邀请仓库成员，不强制组织/项目层级。
历史数据迁移时由部署者显式指定归属，保留原 ID 与历史导入标记。

### 2. 最小身份闭环

运行时切换采用经用户确认的临时只读过渡：HTTP 不再读写原型 JSON，
统一使用 PostgreSQL 身份和仓库读取授权；共享管理员令牌立即失效。
历史协作记录由 `historical_items` 提供只读列表与统计，旧创建/编辑/合并接口明确返回 503，
第 4–6 组领域任务逐步恢复写入；不以历史流水线状态宣称真实 CI。
仓库创建继续可用并绑定当前账号，Git 对象沿用原磁盘目录。

先恢复本地账号：部署者在本机执行一次性管理员引导，随后由管理员创建账号，
公开注册关闭。密码强哈希；网页采用 HttpOnly Cookie 承载短期 JWT，生产设置 Secure、
SameSite 并保留 Origin/CSRF 校验，不在前端本地存储令牌。
现有不透明 Cookie 会话已完成基础撤销验收；它是过渡实现，不代表新 JWT 方案已交付。
JWT 有效期以 15 分钟为默认，绑定用户及持久会话 ID，校验签名、固定允许算法、
issuer、audience 和有效期后仍查询会话撤销及账号状态。角色不固化到 JWT 中。
签名密钥从外部配置提供，支持有界的旧验证密钥轮换窗口；未配置时拒绝启用签发，
不生成启动即丢失的临时密钥，也不使用 JWT 自带算法或任意远程 key URL 决定信任。
相比完全无状态 JWT，此方式保留查询成本，但满足退出和停用立即失效的既有契约。

刷新凭据为高熵随机值，通过独立 HttpOnly Cookie 交付；数据库保存摘要、有效期、
刷新链与已使用状态。事务轮换保证一次性使用，已使用凭据重放撤销整条链及关联会话；
前端统一协调续期请求，不让多个组件自动并发刷新。退出同时撤销链和会话并清理 Cookie。
刷新链有可配置的绝对到期时间，不因持续使用无限延长；JWT 和刷新原文不进入日志、
SSR HTML、Query 缓存或本地存储。HttpOnly 不能阻止 XSS 借浏览器发请求，仍需安全渲染。

PAT 作为 API Token 保留，随机生成、只展示一次、摘要落库、限定权限和期限，Git Basic 密码位携带 PAT。
每次请求核对账号状态与成员权限；不保留共享管理员令牌作为权限后门。
GitHub 等外部身份登录继续延后；下述 OAuth 是本平台向客户端/第三方授权，不是外部登录。

### 3. git2、标准 Git 传输与统一授权

引入 `git2` 用于仓库初始化、对象/引用读取及版本浏览，将阻塞的原生调用隔离到阻塞任务，
以已验证仓库 ID 定位裸仓库，不让用户输入选择任意磁盘路径。
系统 Git 的 Smart HTTP 后端继续负责 upload-pack/receive-pack 标准协议，不手写 packfile；
`git2` 的客户端 RemoteCallbacks 不是服务端 sideband 接口，不能单靠添加 crate 就获得 remote 提示。
相比全量重写服务端 Git 协议，此分层满足引入 git2 的要求且复用成熟传输实现。
先权限检查，再启动有超时、资源和流量限制的 Git 子进程。
浏览与传输共用仓库权限；受保护分支必须在引用写入前校验，
不能只在 push 返回后检查。成功事件记录引用前后 SHA，按事件键去重。

维护公告和彩蛋通过授权后的统一消息选择器产生，作为协商后的标准 sideband 进度消息发送；
receive-pack hook 只覆盖 push，fetch/pull 必须单独验证 upload-pack 的消息接入。
实现前先以真实客户端证明两条链路，禁止直接拼接裸文本到引用广告或 pack 字节。
消息有长度/数量上限，过滤 ANSI、控制字符和不可信模板，失败只跳过消息，不改变 Git 结果。
无更新、静默或未协商进度时不保证显示；不伪造推拉成功来显示公告。
生日祝贺复用个性化消息入口，采用显式 opt-in，默认关闭；只有用户主动填写月日、选择时区并开启后才匹配。
不收集出生年份，不从提交作者、邮箱或第三方资料推断；无填写、未开启、关闭或删除后均不发送。
仅按本次 Git 认证账号及其选择的时区判断月日，2 月 29 日按精确日期匹配，
非闰年不自行改为其他日期。用户可随时修改、关闭或删除，后续请求读取当前设置。
个人设置仅本人可读写，不进入公共资料、匿名响应、OAuth 默认 scope、Git 对象或消息日志；
只向本次已认证用户发送通用祝贺，不在提示里输出生日资料。

### 4. 工作区快照与显式集成

分别持久化讨论上下文、工作区和不可变已提交版本；checkout 可重建。
首版只支持仓库内源分支，不支持 fork MR 或未提交编辑同步。
MR 版本记录 merge base、source 和 target SHA；评论保留版本归属，
批准在源版本变化后失效。CI 同样绑定版本，不用分支名替代 SHA。
集成操作写入持久意图，Git 使用旧值比较更新；数据库状态失败由恢复流程对账。
目标变化时重新计算并要求确认，禁止无提示合并未展示版本。

参考：
- https://delta.dev/docs/concepts/core-concepts
- https://delta.dev/docs/concepts/delta-and-git
- https://delta.dev/docs/concepts/worktrees

### 5. 独立 gRPC Runner

新增版本化 protobuf（`wuling.runner.v1`），Rust 控制面与独立 Rust Runner
使用生成代码；浏览器继续调用 HTTP，不引入 gRPC-Web。
RPC 覆盖注册、心跳、领取、日志、step 状态和完成。
数据库原子领取任务并生成 attempt/租约；迟到 attempt 拒绝，重试有界，
日志按 attempt 与序号幂等写入，完成重复上报返回相同终态。
控制面负责事件去重和 needs DAG；执行端检出固定 SHA，在专用 Linux 容器执行。
首版日志轮询，优先实现正确性而非双向流复杂度。旧 HTTP Runner 不原样接入。
生产使用 TLS，凭据按 Runner、仓库和任务划分；容器不视为恶意代码充分隔离。

### 6. 前端与机密边界

继续使用 HeroUI React 和已有主题，新增组件不另建配色系统。
TanStack Query 负责按用户/仓库/版本分键的客户端查询和失效；SSR 每请求独立状态，
退出清理私有缓存。长日志/大列表按需要使用 Virtual，不因依赖存在就强制引入。
保留 Nasti 显式路由适配；认证页和编辑/日志为客户端，公开概览 SSR。
新增登录、成员、API Token 页面只调用 Cookie 认证 API，不处理 JWT 原文；
JWT 后端和续期接口先通过验收，再完成登录 UI 的最终联测。
OAuth 确认、Device Flow 验证和已授权应用管理同样采用 HeroUI、现有主题与客户端路由。
先做仓库级 Secrets，外部持久密钥加密，只有有效 attempt 获取。
首版所有 MR 工作流默认不注入 Secrets；可信手动/受控 push 工作流方可授权下发。

### 7. OAuth 授权服务器与 Device Flow

为客户端/第三方提供 Authorization Code + PKCE（S256）与 RFC 8628 Device Flow，
不实现 implicit 或密码授权模式。注册记录区分公开和保密客户端，绑定精确 redirect URI、
允许的 grant/scope 和有效状态；公开客户端不依赖嵌入式 client secret，
保密客户端凭据摘要保存。授权页清楚展示客户端和 scope，用户显式确认，不信任第三方页面代批。
授权码短期、单次使用，绑定客户端、redirect URI、用户和 code challenge；
授权响应保持 state，客户端集成说明要求验证 state，拒绝开放重定向和宽泛 URI 通配。

设备授权分别保存高熵 device code 摘要、人类可输入的 user code、期限、轮询间隔与状态。
验证页面仅在核对代码、客户端和 scope 后接受批准/拒绝；
轮询事务化处理 pending、slow_down、denied、expired 和单次领取，不因网页访问自动批准。
限制设备码申请、user code 猜测和轮询速率；不在页面或日志暴露 device code。

OAuth 授权、访问凭据与轮换刷新链独立于网页会话，访问/刷新原文仅通过协议响应交给客户端，
服务端摘要存储。每次请求将 scope 与当前用户/仓库权限取交集；撤销应用、停用账号和
刷新重放立即使对应授权失效。API Token 可独立撤销，不被误当成 OAuth 授权或网页 JWT。
用户可查看/撤销已授权应用；Runner 注册与任务凭据继续使用独立信任边界。
相较直接把网页 JWT 交给第三方，此方案增加授权状态，但避免混淆 Cookie、受众与撤销范围。

## Risks / Trade-offs

- [数据库增加部署成本] → 同步更新本地与 Nix 入口，提供健康检查和迁移说明。
- [Git 与 SQL 无跨存储事务] → 持久集成意图、引用旧值比较、故障注入与启动对账。
- [副作用任务无法真正 exactly-once] → attempt fencing、有界重试，文档明确任务需幂等。
- [Secret 变形无法完全脱敏] → 跨块原文脱敏，不可信 MR 不发机密，禁止主动打印凭据。
- [Nasti 适配器升级风险] → 保留真实构建/SSR 测试，增加公开页和私有跨账号测试。
- [JWT Cookie 被误当作无 XSS/CSRF 风险] → 禁止脚本存储原文，保留安全渲染、来源校验和服务端撤销。
- [刷新并发被识别为重放] → 前端统一续期入口，事务化轮换，测试多标签页和并发失效反馈。
- [OAuth/设备码被截获或暴力猜测] → PKCE、客户端绑定、显式确认、期限、限速与单次领取。
- [git2 原生依赖与 remote 提示破坏协议] → 普通/Nix 构建及许可证核验，真实 push/fetch 对照测试。
- [恢复范围较大] → tasks 按四批验收，不以整个提案存在来宣称功能完成。

## Migration Plan

1. 停止写入并备份当前数据目录，记录 JSON 与仓库引用校验。
2. 创建新数据库并运行迁移；以显式账号映射导入元数据，不移动 Git 对象。
3. 验证 ID、可见性、记录数量、内容和引用一致性，再切换新服务。
4. 不启用新 Runner 前核验 gRPC 身份与消息上限，禁止新旧客户端混用。
5. 切换后如需回退，停止新写入并恢复备份；不得直接启动旧版本读取新数据。
   新写入的保存/导出需单独核对，备份回退不保证保留切换后的数据。
6. JWT 切换采用显式升级：备份数据库、配置外部签名密钥并迁移会话/刷新链，
   旧不透明网页 Cookie 失效，用户重新登录；API Token 不因 Cookie 格式变更被重签或泄露。
   对照验证错误签名、撤销、续期与来源校验后再切前端，不保留旧 Cookie 鉴权旁路。
7. OAuth 客户端和授权数据迁移完成后启用授权端点，使用测试客户端验收 PKCE 与 Device Flow；
   回退停用新签发入口并撤销受影响授权，不把已发第三方凭据转换成网页会话。
